- (constraint) The final PRD binds the spine: Vietnam-first, one Legal Seller, one inventory location, health supplements only; medicine, marketplace, multi-warehouse, public APIs, dedicated search infrastructure, and microservices are outside MVP.
- (direction) Fast path is used because the user asked to continue without further discovery. The deliverables are a build-substrate spine and a Supervisor-Lead-Peer delivery-topology companion.
- (decision) Use a DDD bounded-context modular monolith with hexagonal architecture and vertical use-case slices inside each module. This binds all backend units and prevents shared-layer and shared-database logic from becoming the de facto domain model.
- (decision) Use one monorepo and one release train containing Storefront, Admin, API, and Worker processes. API and Worker share the same module packages and release version; independent scaling does not make them microservices.
- (decision) Bounded contexts are Identity, Content, Catalog, Inventory, Cart, Pricing, Checkout, Orders, Payments, Fulfillment, Returns, Engagement, Governance, and Reporting. Every business table, command, event, and policy has exactly one owning context.
- (decision) A module may import another module only through its published application contract or immutable event contract. Imports of another module domain, repository, ORM model, or adapter are forbidden; direct cross-module database reads are forbidden.
- (decision) Use one PostgreSQL cluster for MVP with module-owned schema files and tables. Foreign keys and cascades stay inside an owner boundary; cross-boundary references use stable UUIDv7 identifiers and immutable snapshots where agreement history matters.
- (decision) All state changes enter through a command handled by the owning module application layer. HTTP controllers, queue consumers, cron jobs, and provider adapters cannot write repositories directly. Commands carry idempotency and actor/correlation context.
- (decision) Use a transactional outbox in PostgreSQL for cross-module and external events. Delivery is at least once; event envelopes are versioned and immutable; every consumer is idempotent and records processing outcomes.
- (decision) Checkout is a process manager, not an owner of Order, Payment, or Inventory truth. Orders owns the commercial snapshot and order lifecycle; Payments owns provider evidence and refunds; Inventory owns reservations; Fulfillment owns physical work and shipments.
- (decision) Inventory exposes reserve, confirm, and release commands keyed by Order and line. Available quantity equals on-hand minus active reservations; expiry and release are idempotent; only Inventory can mutate Stock Position.
- (decision) Search starts as a replaceable PostgreSQL-backed read projection built from Catalog, Content, Price, and Availability events. Search cannot become a source of truth. Extract only when measured relevance, latency, or indexing throughput breaches accepted SLOs.
- (decision) Payment integrations use hosted or redirected provider UI behind a Payments-owned port. Only verified server-to-server evidence can advance Payment; browser returns are informational; raw account data cannot enter Ecom storage, logs, or analytics.
- (decision) Expose REST APIs under /api/v1 with an OpenAPI contract, RFC 9457 problem details, UTC ISO 8601 timestamps, VND amounts as integer minor units, and cursor pagination. Webhooks require signature verification, replay defense, and idempotency keys.
- (decision) Use UUIDv7 primary identifiers, lowercase kebab-case event names, past-tense event names, and schema-versioned envelopes containing eventId, eventType, occurredAt, producer, aggregateId, schemaVersion, correlationId, causationId, and payload.
- (decision) RBAC is enforced in API application policies, not UI visibility. Governance owns append-only audit evidence and privacy workflows; modules emit auditable facts while Governance cannot rewrite source business state.
- (decision) Seed toolchain: Node.js 24.16.0 LTS, pnpm 11.4.0, TypeScript 6.0.3, NestJS 11.1.24, Prisma ORM 7.9.0, PostgreSQL 18.6, Redis Open Source 8.10.0, and BullMQ 5.77.6.
- (version) Next.js 16.2.11 is the verified Active LTS baseline on 2026-08-25, but the vendor announced a security patch for 2026-08-26. The exact Next.js patch must be re-verified and pinned before scaffolding; no vulnerable baseline may be adopted.
- (decision) Use Next.js 16.2 Active LTS line for Storefront and Admin, pinned to the latest vendor-patched release available at scaffolding. Avoid experimental framework features in launch-essential paths.
- (decision) Environments are local, test, staging, and production. Production uses containerized Web, API, and Worker processes with managed PostgreSQL, managed Redis, S3-compatible object storage plus CDN, edge TLS/WAF, and vendor-neutral OTLP telemetry. Cloud vendor remains deferred.
- (decision) Operational readiness follows PRD LG-5 through LG-7: production-like capacity tests, backup restore rehearsal, payment replay, order-refund drill, correlation-based alerts, and zero unresolved critical or high launch-surface findings.
- (decision) Extraction follows the strangler pattern only after evidence. Candidate order is Search, Payments, then Inventory; extraction requires an accepted bottleneck record, owned contract, independent data migration plan, shadow or dual-read validation, and rollback.
- (decision) Architecture tests enforce module import boundaries, public contract compatibility, database ownership, event schema compatibility, and prohibited direct adapter-to-repository mutations. Provider sandboxes and replay suites are required before production.
- (decision) Supervisor owns PRD and architecture gates, dependency policy, release acceptance, and Beads graph health. Leads own coherent context groups and published contracts. Peers own stories inside one module; cross-module changes require an explicit contract issue and Lead review.
- (decision) BR records epics, stories, gates, dependencies, and ownership; BV is the read-only dependency and priority view. Srcwalk is required before structural code changes and for impact review; UBS scans changed code before handoff. CASS is not part of the workflow.
- (assumption) The default deployment is regionally close to Vietnam and uses provider-neutral managed services. Exact cloud, payment provider, carrier, object storage, email, and SMS selections close through LG-3 and architecture implementation records.
- (question) Confirm at scaffold time the patched Next.js Active LTS version and run a Prisma 7.9 migration and transaction spike against PostgreSQL 18.6 before accepting the dependency lock.
- (decision) Reconciliation override: AD-13 must preserve every LG-1 through LG-7 artifact and blocking effect, not only production operations gates.
- (decision) Discovery is an explicit bounded context owning the search and combined commercial-visibility projections. Regulatory invalidation uses a synchronous fail-closed tombstone path; ordinary non-safety projection lag is bounded through LG-5.
- (decision) Finance is the authoritative internal financial ledger and electronic-invoice evidence owner for MVP. Payments reconciliation is operational evidence; Payments posts immutable captured, refunded, and settlement facts to Finance through idempotent contracts.
- (decision) Merchant owns Legal Seller identity and verification. Pricing Offers reference a merchantPartyId; Orders, Finance, and invoice evidence snapshot the legal party. Marketplace behavior remains deferred and is not represented by a generic sellerId convention.
- (decision) Governance coordinates privacy, retention, legal hold, processor and transfer registers, and authority-response cases. Every data owner publishes discover, export, correct, erase or anonymize, hold, and evidence-result contracts without surrendering source ownership.
- (decision) Regulated publication records exact approved evidence, claim, Disclaimer, reviewer, advertising classification, and human approver versions. Evidence withdrawal synchronously fails closed across Content, Discovery, caches, related products, and outbound availability notifications.
- (decision) Frontend precedence is PRD outcomes, then approved page specification, then approved global tokens, then generated design candidates. Shared UI primitives own semantics and focus behavior; one semantic content source serves every breakpoint; animation is progressive enhancement.
- (decision) Release sequencing is binding: launch-essential work can gate first controlled sale; evidence-triggered follow-ons cannot gate it unless LG-4 requires them; Later items require a PRD scope decision.
- (decision) Reconciliation override: Redis and BullMQ are removed from the launch seed. The Worker leases PostgreSQL outbox and durable job records for MVP; Redis caching or BullMQ requires accepted load or job-throughput evidence.
- (decision) Application processes are stateless; sessions, schedules, idempotency, uploads, and jobs use shared durable stores. Read replicas are deferred and may serve only owner-approved or derived reads within a staleness budget, never authoritative command validation.
- (decision) Engagement owns restricted customer service notes and exposes only minimal Order-linked support facts under server-side restricted authorization and audited commands.
- (decision) Application-facing /api/v1 and OpenAPI contracts are internal Storefront/Admin interfaces for MVP, not a public developer product. Notification channels remain provider-neutral until LG-3.
- (decision) Checkout owns the canonical PurchaseEligibility v1 decision contract and conformance fixtures; deny precedence is Catalog regulatory eligibility, Offer validity, Inventory availability, and policy limits. Discovery projects the same contract and Checkout re-evaluates it authoritatively.
- (decision) Checkout allocates Order and line UUIDv7 identifiers and is the sole process owner from reservation through Payment-to-Order transition. Late or contradictory evidence enters On Hold and reconciliation; other modules do not issue competing Order lifecycle commands.
- (decision) Orders owns Refund monetary allocation from immutable commercial and policy snapshots. Returns supplies approved item quantities and reasons; Orders emits one ApprovedRefundInstruction; Payments executes it exactly and Finance posts it.
- (decision) Catalog owns a synchronously queried Safety Denial Registry updated in the same transaction as regulatory withdrawal. Every public response and outbound Product notification fails closed against it; outbox events perform asynchronous cleanup only.
- (decision) Cross-owner protocols use canonical identities and envelopes: MerchantPartySnapshot, regulated evidence references, FinancialFact, ApprovedRefundInstruction, GovernanceCase, and idempotent command identity.
- (decision) Rolling deployment uses an expand-migrate-contract window of at least one release. Platform owns global database objects and migration ordering; event consumers precede producers, old versions remain decodable until drain evidence, and destructive contraction waits for old processes and messages to disappear.
- (decision) Object blobs remain owned by the source business module through private owner ports and opaque namespaces. Regulatory evidence is immutable/versioned; erase, hold, and export participate in Governance cases.
- (decision) Storefront owns one shell contract and global regions; route epics provide slots and cannot reimplement header, navigation, cart/account access, or compliance footer.
- (decision) Cross-module contracts require producer ownership, consumer Lead acceptance, BR producer-to-consumer dependencies, compatibility evidence, and Supervisor resolution before a breaking exception merges.
- (decision) A versioned gate evidence manifest binds launch gate dependencies to artifacts. CI verifies purpose registries, Governance owner coverage, accessibility evidence, contract compatibility, and gate evidence links.
- (decision) Infrastructure selection is an Architecture-owned LG-5 precursor that blocks environment and CI/CD provisioning until cloud, region, runtime, managed-service classes, residency, backup, cost, and exit assumptions are accepted.
- (version) Stack seed updated from official current sources on 2026-08-25: Node.js 24.19.0 LTS, pnpm 11.24.0, Next.js 16.3.3 security baseline, NestJS 11.2.3, Prisma 7.10.0, PostgreSQL 18.6. TypeScript 6.0.3 is an explicit compatibility hold pending a TypeScript 7 build spike.
- (decision) Prisma 7 uses ESM, the PostgreSQL driver adapter, and explicit pool and transaction timeout configuration. OpenAPI is 3.2.0 and LG-6 evidence uses OWASP ASVS 5.0.0 version-qualified requirement identifiers.
- (decision) Refund entitlement is atomically reserved by Orders with optimistic version or serialization; Payments independently enforces the transactional cumulative cap captured minus refunded minus in-flight authorized.
- (decision) A verified Payment success after terminal Order cancellation never reopens or holds the Order. Payments creates a reconciliation exception, blocks Fulfillment, and initiates the approved corrective Refund or audited correction path.
- (decision) Inventory reservation performs availability check and reservation creation atomically under conditional version or row serialization and enforces nonnegative availability. All reservation transitions are conditional and concurrency-tested.
- (decision) Authorization is enforced at every owning application-command boundary for HTTP, worker, schedule, event, provider, human, and service actors with least-privilege capability and resource scope.
- (decision) Untrusted uploads are quarantined, type and size validated, malware scanned, safely transformed, and served from an isolated origin with restrictive headers. Active SVG, HTML, and PDF are never inlined; regulated originals remain immutable with safe access paths.
- (decision) RefundApproval has explicit authorized sources: Returns for post-fulfillment returns, Orders for policy-approved pre-fulfillment cancellation, and Payments Reconciliation plus an authorized Operator for success-after-terminal-cancel or provider correction. Orders remains the sole monetary calculator and entitlement reserver.
